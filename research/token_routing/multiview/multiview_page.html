Runs

eval_size 500 per cell; per-cell binomial SE 0.006 to 0.021, so the 8-cell mean carries about ±0.005 from eval noise. Seed-to-seed spread of the recipe at f3904 is about ±0.01 (sk3 vs sk3sd1: 0.903 vs 0.914), so a single seed resolves differences of roughly 0.015.

Per-cell scores

What runs

  • View 1: the ordinary routed forward with the graph split at block 7; h7 is cached detached.
  • Views 2..k: blocks 7-31 + head only, from the cached h7, each with a fresh random 20% / 7% subset of every document's tokens. A full optimizer step on the late parameters between views.
  • Then one backward through blocks 0-6 with the mean of the k views' dL/dh7, and the trainer's normal step.
  • Mean, not last view: each view's dL/dh7 is an independent draw for a different subset, so averaging lowers variance at no extra FLOPs.

FLOP meter check

Repeat views log no example lengths and are charged late blocks + head at the kept length only. On identical rows (6 Beaker steps): dense-equivalent 19.694 PF for both, actual 5.981 PF at k = 1 and 7.438 PF at k = 2. So a second view costs 0.089× dense per step, about 54% of a whole routed step.

Full run: k = 2 at f1952 metered 483.0 PF (0.310× dense) vs the recipe's 345 PF.

Limits

  • One seed per cell. Views use random token choice (it ties the router at f3904: 0.914 vs 0.915); the recipe curve uses the router. The k = 1 random-choice run at f1952 on the same code path is the direct control.
  • Repeated views see the same answer labels, so the late stack gets a partial second epoch per row.
  • Three Beaker runs were preempted and restarted from step 0; their FLOP totals come from the final, uninterrupted attempt.
